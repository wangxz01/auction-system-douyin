# AI 使用说明

## 1. AI 在项目中的角色

AI 主要承担执行辅助和审查辅助：

- 快速阅读代码并定位风险点
- 生成后端测试样例
- 补齐重复性接口和前端页面样板
- 整理 README 和方案文档
- 根据测试失败信息辅助定位问题

AI 不直接决定核心交易规则，关键设计由人工确认后再实现。

## 2. 人工把控的关键决策

| 决策点 | 人工把控原因 |
|---|---|
| 金额用 `*_cents` 整数字段 | 避免浮点精度影响交易规则 |
| MySQL 行锁作为一致性兜底 | Redis 不应成为唯一正确性来源 |
| `client_bid_id` 幂等键 | 防止重复点击或网络重试重复落库 |
| 状态机不可逆 | 避免订单和竞拍状态反复变化 |
| 订单权限保护 | 防止知道 auction id 就能查看他人订单 |
| `ADMIN_USERNAMES` 管理员策略 | 适合开发演示，后续可演进为正式 RBAC |

## 3. AI 代码使用边界

- AI 生成代码必须经过人工 diff。
- 核心交易链路必须有自动化测试。
- 不能把无法解释的生成代码合入核心路径。
- 不能把外部资料中的密钥、账号密码或敏感信息复制进仓库。
- 通过 `go test`、`npm run lint`、`npm run build` 后才能提交。

## 4. 典型 Prompt

### 并发风险分析

```text
检查这个出价接口在并发情况下是否会出现低价覆盖高价、重复订单或 winner 错误，并给出可测试的修复方案。
```

### 测试补齐

```text
为 0 元起拍、自动延时、封顶成交、重复 client_bid_id、并发出价写后端测试，先验证当前行为是否失败。
```

### 权限审查

```text
从攻击者视角检查订单、商家后台、上传、WebSocket 和评论接口是否存在越权或未鉴权问题。
```

### 文档整理

```text
把当前项目实现整理成评审可读的方案文档，重点突出实时同步、并发控制、幂等和 AI 使用边界。
```

## 5. AI 贡献率评估

AI 适合承担：

- 样板代码
- 测试用例
- 文档初稿
- 风险点清单
- 重复接口串联

人工必须把控：

- 交易规则
- 一致性边界
- 安全权限
- 演示取舍
- 是否合入主分支

因此本项目不追求 AI 代码比例越高越好，而是追求关键决策可解释、核心路径可测试、最终结果可复现。
