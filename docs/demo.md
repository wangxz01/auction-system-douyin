# 演示闭环脚本

目标是在 3 到 5 分钟内稳定展示“商品上架 -> 规则配置 -> 实时出价 -> 动态排名 -> 竞拍成交 -> 订单查看”的完整闭环。

## 演示账号

| 角色 | 账号 | 说明 |
|---|---|---|
| 超级管理员 | `admin` | 已通过 `ADMIN_USERNAMES=admin` 配置为管理员 |
| 商家 A | `demo-merchant-1` / `demo1234` | 东方艺术廊，拥有多场已进行拍卖 |
| 商家 B | `demo-merchant-2` / `demo1234` | 珍藏阁，拥有 pending 拍卖「当代名家国画《山居图》」 |
| 用户 A | `demo-buyer-3` / `demo1234` | 用于第一轮出价 |
| 用户 B | `demo-buyer-7` / `demo1234` | 用于超越用户 A |

演示种子账号统一弱密码 `demo1234`，只用于本地/受控演示；真实管理员密码不要写进公开材料。

## 演示数据准备

首次演示前在 `backend/.env` 打开：

```dotenv
SEED_DEMO_DATA=true
ADMIN_USERNAMES=admin
```

重启后端后会自动灌入 14 个演示账号、8 场拍卖、出价历史、评论历史、行为埋点和 1 笔订单。完整名单见 [docs/演示数据.md](./演示数据.md)。

## 演示商品参数

| 字段 | 建议值 |
|---|---|
| 商品名称 | 演示竞拍商品 |
| 起拍价 | 0 |
| 加价幅度 | 10 |
| 封顶价 | 50 |
| 竞拍时长 | 60 秒 |
| 自动延时 | 10 秒 |
| 直播地址 | 留空，使用本地 `public/live.mp4` 演示视频 |

## 操作步骤

1. 启动 MySQL / Redis / 后端 / 前端。
2. 使用 `admin` 登录前端，进入 `/admin` 查看 8 场预置拍卖和底部 `Demo Users` 面板。
3. 打开用户端窗口 A，登录 `demo-buyer-3`，进入任意 active 拍卖直播间。
4. 打开隐身窗口 B，登录 `demo-buyer-7`，进入同一拍卖直播间。
5. 用户 A 出价一次，观察当前价、排行榜、领先提示和视频区浮层。
6. 用户 B 反向出价，观察用户 A 的“被超越”提示、排行榜变化和 WebSocket 同步。
7. `admin` 回到 `/admin`，对该拍卖点击 `Finish`，演示强制成交和订单生成。
8. 中标用户进入订单页查看订单并模拟支付。
9. `admin` 进入 `/admin/orders` 查看成交订单。
10. 进入 `/admin` 底部 `Demo Users`，演示删除某个 `demo-` 用户；或进入拍卖详情页演示「删除拍卖」。

备用路径：如果要演示 0 元起拍、封顶价和自动延时的完整配置过程，可进入 `/admin/create` 新建一个 60 秒、封顶 50、自动延时 10 秒的短拍卖。

## 预期现象

| 节点 | 预期现象 |
|---|---|
| 开始竞拍 | 用户端状态从未开始变为进行中 |
| 出价成功 | 当前价刷新、价格动画触发、Top 排行变化 |
| 被超越 | 原领先用户看到被超越 toast |
| 自动延时 | 直播间出现延时提示，结束时间后移 |
| 封顶成交 | 竞拍立即结束并生成订单 |
| 订单查看 | 中标用户能看订单，非中标用户不能看该订单 |
| 商家订单 | 管理后台能看到成交订单 |

## 出错恢复

| 问题 | 恢复方式 |
|---|---|
| 后端改了 `.env` 不生效 | 重启后端 |
| 前端接口 401 | 清理浏览器 localStorage 后重新登录 |
| Redis 未启动 | 系统会降级到 MySQL 行锁；压测 Redis 场景前需要启动 Redis |
| 演示商品状态错了 | 新建一个商品重新演示，不依赖旧数据 |
| WebSocket 断开 | 前端会自动重连；重连成功后会重新拉取详情和统计 |
| 预置数据被删 | 保持 `SEED_DEMO_DATA=true`，清掉 `demo-` 数据后重启后端会重新灌入 |
