# 演示闭环脚本

目标是在 3 到 5 分钟内稳定展示“商品上架 -> 规则配置 -> 实时出价 -> 动态排名 -> 竞拍成交 -> 订单查看”的完整闭环。

## 演示账号

| 角色 | 账号 | 说明 |
|---|---|---|
| 超级管理员 | `admin` | 已通过 `ADMIN_USERNAMES=admin` 配置为管理员 |
| 用户 A | 现场注册或预置账号 | 用于第一轮出价 |
| 用户 B | 现场注册或预置账号 | 用于超越用户 A |

注意：不要在公开材料里写真实密码。演示前在本地确认账号可登录即可。

## 演示商品参数

| 字段 | 建议值 |
|---|---|
| 商品名称 | 演示竞拍商品 |
| 起拍价 | 0 |
| 加价幅度 | 10 |
| 封顶价 | 50 |
| 竞拍时长 | 60 秒 |
| 自动延时 | 10 秒 |
| 直播地址 | 留空，使用本地 `public/live.mp4` 演示视频 |

## 操作步骤

1. 启动 MySQL / Redis / 后端 / 前端。
2. 使用 `admin` 登录前端。
3. 进入 `/admin/create` 发布演示商品。
4. 在 `/admin` 找到商品并点击开始竞拍。
5. 打开两个用户端窗口，分别登录用户 A 和用户 B。
6. 两个窗口都进入同一个 `/auction/:id` 直播间。
7. 用户 A 出价 10，观察当前价、排行榜、领先提示。
8. 用户 B 出价 20，观察用户 A 的“被超越”提示和排行榜变化。
9. 在倒计时最后 10 秒内继续出价，观察自动延时提示和毫秒倒计时更新。
10. 出价到 50 触发封顶价成交。
11. 中标用户进入订单页查看订单并模拟支付。
12. `admin` 进入 `/admin/orders` 查看成交订单。

## 预期现象

| 节点 | 预期现象 |
|---|---|
| 开始竞拍 | 用户端状态从未开始变为进行中 |
| 出价成功 | 当前价刷新、价格动画触发、Top 排行变化 |
| 被超越 | 原领先用户看到被超越 toast |
| 自动延时 | 直播间出现延时提示，结束时间后移 |
| 封顶成交 | 竞拍立即结束并生成订单 |
| 订单查看 | 中标用户能看订单，非中标用户不能看该订单 |
| 商家订单 | 管理后台能看到成交订单 |

## 出错恢复

| 问题 | 恢复方式 |
|---|---|
| 后端改了 `.env` 不生效 | 重启后端 |
| 前端接口 401 | 清理浏览器 localStorage 后重新登录 |
| Redis 未启动 | 系统会降级到 MySQL 行锁；压测 Redis 场景前需要启动 Redis |
| 演示商品状态错了 | 新建一个商品重新演示，不依赖旧数据 |
| WebSocket 断开 | 前端会自动重连；重连成功后会重新拉取详情和统计 |
